## 一、项目概述

### 1.1 背景与目标

针对初创公司 "客户分层模糊、合同流程松散、履约跟踪滞后" 三大痛点，构建一套轻量化、可追溯的客户合同管理体系。

核心目标：



* **客户管理精细化**：潜在 → 意向 → 成交 → 复购 四层客户全生命周期管理

* **合同流程规范化**：模板库 → 在线编辑 → 审批 → 签章 → 归档 全链路

* **履约跟踪实时化**：节点拆分、自动提醒、问题闭环

* **数据驱动决策**：客户留存率、合同履约率、服务满意度自动统计

* **AI 辅助**：本地法规知识库 + 合同风险智能扫描

### 1.2 用户角色



| 角色  | 代号      | 核心权限                     |
| --- | ------- | ------------------------ |
| 销售岗 | SALE    | 客户 CRUD、创建合同、创建工单、查看本人数据 |
| 法务岗 | LEGAL   | 合同审核、模板库维护、查看所有合同        |
| 运营岗 | OPS     | 履约节点处理、工单处理、查看满意度        |
| 创始人 | FOUNDER | 全部模块查看、报表导出、角色权限调整       |
| 管理员 | ADMIN   | 用户管理、知识库维护、系统配置          |

## 四、模块详细设计

### 4.1 客户分层管理模块

**核心逻辑：**



1. **客户层级流转**：

* 潜在 (1) → 意向 (2)：销售标记意向度≥3

* 意向 (2) → 成交 (3)：创建了该客户的生效合同

* 成交 (3) → 复购 (4)：该客户存在≥2 份生效合同

* 所有层级变更自动写入操作日志

1. **联系方式脱敏**：

* 数据库存储：手机号加密存储（AES）

* 前端展示：`139****4567` 格式

* **禁止**提供反查接口（合规要求）

1. **历史合作关联**：

* 客户详情页联查：合同列表 + 履约节点完成率 + 工单数

* 按合同类型、时间范围筛选

### 4.2 合同全周期模块

**核心流程：**



```
销售发起 → 法务审核 → 创始人终审 → 生效 → 归档

&#x20;  ↓驳回      ↓驳回       ↓驳回

&#x20; 草稿       草稿         草稿
```



1. **基于模板创建合同**：

* 选择模板 → 填入金额 / 期限等变量 → 生成草稿

* 关键条款自动校验：金额格式、签字栏非空、日期逻辑（结束日期 > 开始日期）

1. **审批流（Flowable 实现）**：

* 预定义流程：`contract_approval.bpmn20.xml`

* 销售发起 → 法务审核（LEGA 组）→ 创始人终审（FOUNDER 组）

* 驳回回到草稿状态，记录审批意见

1. **电子签章（Mock 版）**：

* 第一版：上传签章图片，前端可拖拽定位

* 生效后合同内容禁止修改（status=3 时内容字段不可更新）

* 生成 "已生效" 水印（后端生成 PDF 时叠加）

1. **归档检索**：

* 合同生效后自动归档

* 支持按合同编号、客户名、日期范围、合同类型组合检索

### 4.3 履约跟踪模块

**核心逻辑：**



1. **节点自动拆分**：

* 合同生效时，根据模板预设的节点清单自动生成履约节点

* 支持手动添加自定义节点

* 每个节点必须有：责任人、截止日期、完成标准

1. **自动提醒（XXL-Job 定时任务）**：

* 每日 09:00 扫描所有未完成节点

* 截止前 3 天：发送系统消息给责任人

* 截止当天：系统消息 + 邮件

* 已逾期：系统消息 + 邮件 + 通知其上级

* 失败重试 3 次，间隔 5 分钟，记录到 remind 表

1. **履约问题闭环**：

* 责任人提交问题 → 上传证明材料 → 状态 "待协调"

* 处理中 → 解决 → 留痕处理结果

### 4.4 客户服务模块

**工单状态机：**



```
待分配(1) ──分配──> 处理中(2) ──提交处理结果──> 待确认(3)

&#x20;  ↑                    │                        │

&#x20;  │                    │                        │客户确认

&#x20;  │                    ↓                        ↓

&#x20;  └────────────── 已驳回(5)               已闭环(4) ──> 推送满意度评分
```



1. **自动分配规则**：

* 履约问题 → 运营岗 (OPS)

* 产品故障 → 技术组（暂归 OPS）

* 服务咨询 → OPS

* 投诉建议 → OPS 负责人

* 支持手动改派

1. **满意度评分**：

* 工单闭环后自动生成评分链接（带 token）

* 客户提交后关联到客户和负责人

* 按月统计各负责人平均分

### 4.5 数据统计模块

**核心指标 SQL 思路：**



| 指标       | 计算方式                                                 |
| -------- | ---------------------------------------------------- |
| 客户总数     | `COUNT(*) FROM customer WHERE status=1`              |
| 各层级占比    | `GROUP BY level`                                     |
| 客户留存率    | 本层级客户数 / 总客户数                                        |
| 合同总数     | `COUNT(*) FROM contract WHERE status IN(3,5)`        |
| 合同履约率    | 已完成节点数 / 总节点数（按合同分组）                                 |
| 工单平均解决时效 | `AVG(TIMESTAMPDIFF(HOUR, create_time, finish_time))` |
| 满意度分布    | `GROUP BY score`                                     |

**报表导出**：



* 用 EasyExcel 导出 Excel

* 用 iText / OpenPDF 生成 PDF（含 ECharts 图表截图）

* 第一版可以只做 Excel 导出，PDF 后续再加

### 4.6 权限管理模块

**RBAC 实现：**



* Sa-Token 的 `@SaCheckPermission` 注解控制接口级权限

* 数据权限：销售只能看自己创建的客户 / 合同（MyBatis-Plus 拦截器自动拼 `owner_id = 当前用户`）

* 操作日志：自定义 `@OperationLog` 注解 + AOP 切面，自动记录

### 4.7 AI 合同助手

**RAG 链路：**



```
上传法规文档 → 解析(PDF提取文本) → 切分(chunk=500字, overlap=50)

→ 向量化(embedding API) → 存入Chroma

&#x20;                                             ↓

用户编辑合同 → 合同文本向量化 → 检索Top5相关法规条款

{retrieved\_laws}

请识别合同中的风险点，输出JSON格式：

&#x20; {"clause": "风险条款原文", "risk": "风险描述", "suggestion": "修改建议"}

]
```
